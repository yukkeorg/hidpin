# RP2350 のエラッタ E9 は申告してホストで警告し、プルダウンを拒否しない

[English](0004-report-rp2350-e9-not-refuse.md) | **日本語**

RP2350 の初期の版（A2）では、入力のピンの電圧が論理レベルの中間に入ると電流が漏れて約 2.2 V に保たれ、内蔵プルダウンでは引き下げられない（エラッタ RP2350-E9。A4 版で修正）。
そのため、プルダウンで監視するピン（`mode` = 3）は、開放すると HIGH を読み続けることがある。
チップの版はボードの種類からは分からず、デバイスだけが Pico SDK の `rp2350_chip_version()` で読める。
そこでデバイスは、チップの種類と版、`PULL_DOWN_UNRELIABLE` のフラグを、デバイス情報の予約領域で申告する（PROTOCOL-ja.md 5.2、5.3）。これはプロトコル版 1 のまま行える互換性のある変更である。
デバイスは `mode` = 3 をそのまま受け付け、警告はホストが出す。Python のライブラリは `warnings.warn` で、両方の CLI は標準エラーに出す。
Go のライブラリは、Go のライブラリの通例どおり自分では何も出力せず、`DeviceInfo.PullDownUnreliable()` で呼び出し側に判断を任せる。

## Considered Options

- 文書で注意するだけ: 設定は黙ったまま期待どおりに動かず、使う人は理由が分からないまま LOW にならないピンを見ることになる。
- A2 版では `mode` = 3 を拒否する: 低いインピーダンス（8.2 kΩ 以下の抵抗やプッシュプルの出力）で駆動される入力は A2 版でも正しく動くので、正しい配線まで使えなくなる。また、同じホストのプログラムが、チップの版によって成功したり失敗したりする。

## Consequences

- これらの欄より前のファームウェアは 0 を送るので、ホストは判断できず警告しない。この版以降のファームウェアは必ずチップを申告する。
- 警告は、今回変えたピンだけでなく、書き込んだ後の設定にプルダウンのピンが残っていれば毎回出す。設定が続く限り危うさも続くためである。
