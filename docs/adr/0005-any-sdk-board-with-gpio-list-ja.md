# Pico SDK のどのボード向けにもビルドでき、利用可能GPIOはビルド時に指定する

[English](0005-any-sdk-board-with-gpio-list.md) | **日本語**

これまでファームウェアは 3 種類のボードしか受け付けず、ボード種別と利用可能GPIOをソースに書いていた。RP2040 / RP2350 のボードは数が多く、一つずつソースに加えていくのでは追いつかない。
そこで、Pico SDK にある RP2040 / RP2350A のどのボード向けにもビルドできるようにした。`PICO_BOARD` は残す。SDK はピン以外にも、フラッシュの種類とサイズ、水晶発振器の起動待ち、RP2350 が A と B のどちらのパッケージかをここから決めるためである。チップは SDK から読み取り、hidpin のボードごとのコードはなくした。
利用可能GPIOは、構成するときに `-DHIDPIN_GPIOS=0-22,26-28` のような一覧で指定する。Pico、Pico 2、QT Py RP2040 はボード種別（1〜3）つきのプリセットを残す。それ以外のボードは一覧の指定が必須で、ボード種別 0 を送り、デバイス情報で Pico SDK のボード名を申告する（`sdk_board`、PROTOCOL-ja.md 5.4）。これはプロトコル版 1 のまま行える互換性のある変更である。

## 検討した選択肢

- 一覧がなければ 30 本すべてを使う: ボードによっては GPIO が基板上の部品につながっている（Pico 2 の電源モード、VBUS・VSYS の検出、Pico W の無線チップなど）。そこにプルアップをかけたり出力したりするとボードの動作を乱しかねない。指定を必須にすれば、ビルドする人が回路図を確かめることになる。
- RP2350B のボードで GPIO0〜29 だけを使う: B パッケージは 48 本あり、プロトコル版 1 では残りの 18 本を表せない。そのためビルドを止める（PROTOCOL-ja.md 9 で、このようなチップは後の版に回している）。
- `board` = 0 だけを送り、名前は送らない: どのボードと通信しているのかを、ホストが利用者に示せない。
- GPIO を 16 進のマスクで指定する: 番号と範囲の一覧のほうが読みやすく、ピン配置図と照らし合わせやすい。

## 結果

- 次の場合は構成の時点でエラーになる: プリセットのないボードで `HIDPIN_GPIOS` がない、ボードが RP2350B、一覧の書式が誤っている、GPIO0〜29 の範囲外、`HIDPIN_STATUS_LED_PIN` で指定した状態 LED の GPIO を含む。ボードのヘッダーでしか分からないボード自身の LED を含む一覧は、コンパイルの時点でエラーになる。
- ボードの LED が WS2812 かどうかはヘッダーでしか分からないので、WS2812 のプログラムは毎回生成する。
- ホストは、ボード種別 0 のボードを Pico SDK のボード名で表示する。この欄より前のファームウェアは空の名前を送る。
